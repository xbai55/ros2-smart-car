# 地图交接与静止图标跳动：只读核查

证据在 output/pose-jump-diagnosis/，本次未改定位代码、未发送车辆控制指令。

电脑数据库最近三次地图准备均保存地图后失败，错误为“自动位姿已失效，请手动定位”；最近两次从开始到失败约 6.2 秒和 3.8 秒，并非 60 秒的交接过期。更早两次为成功记录，不能认定自动交接功能已被移除。至少一次失败发生在 4.0.9 部署之前，不能归因于本轮按钮协议恢复。

最近两次失败窗口，位姿日志里的 x、y 没有变化，朝向变化分别约 0.0014 和 0.0016 弧度；平面速度接近零。这些样本不支持车体明显移动导致失败，但无法排除两次记录之间的里程计瞬时跳变。交接收据仅记 cancelled 布尔值，没有保存触发时原始里程计和具体作废原因，现有日志无法唯一确定作废原因。

当前连续 30 次状态采样均停止，地图位姿持续为 ExtrapolationException；随后获取的 600 条位姿调试记录没有有效地图位姿。当前导航 runtime 为 idle、localized=false，/amcl_pose 无发布者。此时没有有效地图定位，坐标变换异常可能是导航停止后的结果，不能据此断言它就是交接失败的起因。

只读 ROS 采样 6 秒，/odom 唯一发布者为 ekf_filter_node，45 条样本时间戳没有倒退，x、y 范围均为零。未复现正在正常定位时的图标跳动；当前数据不能判定是 AMCL 修正、坐标变换冲突还是界面显示问题。/tf 存在多个不同节点属于常见情况，尚无证据显示同一条变换由多个节点争抢。

后续最小采集：在用户原地重新定位的过程中，只读同步记录 /amcl_pose（含协方差）、/odom、/tf、/tf_static 与界面收到的 map_pose，比较每次图标跳变时各链路变化。交接作废处应增补原因、前后坐标和时间戳记录，随后通过离线回放验证；不能用平滑图标、取消位姿有效性检查来掩盖问题。此次尚未修改或修复定位功能。
