# InsightRover 4.1 实施与部署记录

电脑客户端及车端已配套更新为 4.1.0，面向用户称为 4.1。当前基础防护、主动绕行关闭，原按钮持续按住逻辑不变。已有未提交工作保留，没有提交、回退或覆盖无关改动。

## 已实现

建图交接保留首个失效原因及阶段、前后里程计坐标、朝向、时间戳和坐标系；诊断接口不返回原图或凭据。临时数据未就绪及传输错误进行有界原地重试，沿用既有等待时间和 60 秒交接有效期，不放宽移动或定位阈值。地图加载回执丢失先核对已有加载状态；初始位姿发布结果未知时不重复发送。只有车端仍持有有效且未使用的记录时，才提供“重试自动定位”。重启不恢复位姿授权。

正常的内部地图加载可跨越自己的建图会话转换；外部换图仍拒绝。交接完成后不因 AMCL 后续状态波动重新启用旧交接门控，避免影响后续控制者。

地图图标只使用有效、有限、与当前地图和会话匹配的位姿；建图中还核对变换源时间戳不早于本轮开始时间。导航定位未就绪时明确等待，不把无效坐标零值当位置。未冻结或平滑图标，也未调低定位可靠性标准。

合并烟火与人员倒地视觉分数筛选：设置 → 视觉识别，分别保存候选上报最低分和 DS 告警最低分，默认 0.5 和 0.8。DS 复核启用时，只对明确支持且达到阈值的结果提示；低分、不确定或失败保留候选。详情见 visual-score-gating-4.0.10.md。未经概率校准，不宣称分数等于真实发生概率。DS 未启用时的本地识别路径已在设置中说明。

通知下拉栏增加“全部已读”：仅原子更新当前账户当时未读记录，不删除通知、不修改异常处理状态。返回实际更新 ID，前端只更新这些通知，后到通知保持未读；处理中与无未读时禁用，失败保留原状态并显示原因。没有对真实用户账户执行批量标记。

## 接口

新增车端 POST /api/navigation/handoff-diagnostic，按交接或请求标识查询阶段、有效性、首个失效原因和是否已发布位姿。交接瞬时错误使用带 code、message、retryable 的 503；终止错误不自动重试。

新增业务 POST /api/v1/maps/slam/preparations/{id}/retry，仅原操作者、有地图和控制权限、车辆绑定未变、未被新控制者接管且车端记录有效时接受；沿用原地图与交接记录，不持久化可重放的位姿。

新增 POST /api/v1/notifications/read-all，返回 updated_count 和 read_ids，仅作用于已鉴权账户。保留视觉阈值 GET/PUT /api/v1/incidents/safety/thresholds。

## 验证与实际限制

后端全量 252 项、前端 127 项通过，TypeScript/Vite 构建通过。车端全量阶段 538 项及 5 个子测试通过，排除两项之前已确认的原有失败；后续完成状态与位姿时间戳变化的相关 50 项专项通过。覆盖位姿只发送一次、发送结果不明、加载回执丢失、瞬时就绪失败、真实移动、首因保留、地图身份不匹配、通知账户隔离与幂等。

静止建图交接完成两轮：第一轮为诊断车端配原 4.0.9 主机；第二轮为最终车端配已安装 4.1.0。两轮均自动复用当前位置、定位就绪并确认停车；没有发送前进、横移、转向或非零速度，没有启动实际导航任务。最终静止测试创建了明确命名的验证地图并将其选为当前地图，原业务地图完整保留。使用业务任务前应在地图管理选择所需地图，验证地图不是行驶场景验收地图。

最终轮 30 个有效位姿样本约 9 秒内 x 跨度 1.18 厘米、y 跨度 1.62 厘米、朝向跨度约 2.9 度。仍有估计变化，不能宣称定位图标绝对静止或现场定位精度已经验收。历史偶发“自动位姿失效”本轮没有复现，原始根因尚未确认；已增加首因诊断以支持后续定位，不能把两次成功等同于故障已彻底消失。

安装程序版本、二进制与内置界面哈希、状态推送、视觉设置回执、通知接口注册及原按钮停止协议均核验通过。最终 /cmd_vel 唯一发布者为 decision_controller，连续只读采样为零，控制权无人持有。未真实调用 DS 评估新提示词的误报率。
