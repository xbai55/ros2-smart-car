# 基础防护默认实现与验证记录

2026-11-16。本次仅在本地修改和验证，没有部署、连接实车、发布 ROS 指令或控制车辆运动。

## 使用行为

设置 → 运动防护可以开启完整防护模式。首次安装及旧配置迁移默认为基础防护、主动绕行关闭；两个选择分别保存，进入导航、搜索、跟随或建图不会自动改变防护模式。

基础防护保留急停、按住驾驶/松手停车、有效期检查、控制权互斥、限速、雷达有效性、方向防撞和转动扫掠检查。导航的地图和定位、跟随目标、巡逻搜索心跳仍是相应任务的必要条件，不扩散为其他控制者的门控。

基础模式关闭主动绕行时，局部防撞不再依赖里程计位姿或 `odom→base_link`，但仍要求新鲜雷达、雷达安装变换及有效底盘速度。速度直接从 `/odom` 的 twist 独立校验；位姿无效不会使有效速度失效，速度本身过期、非有限或缺少必要的车体安装变换仍会停车。雷达及速度数据的原始期限不会因接收或重试延长。

局部检查复用矩形车体扫掠几何，用最近速度及输出历史扩大制动和扫描延迟包络，并覆盖扫描后车体旋转造成的整段轨迹不确定性。允许远离前障的安全后退及横移，旋转仍检查车体角点；未知区域不会改成已观测空闲区域。默认关闭无回波按空旷处理的假设，没有扩大自体过滤或缩小车体。

开启完整防护后，保留位姿新鲜度、连续性及扫描时刻里程计变换检查。开启本地主动绕行时，规划器同样需要这些数据；关闭本地绕行不关闭 Nav2 自身的路径规划。视觉安全事件识别未随防护设置关闭。

基础防护干预后，条件恢复只表示可以重新操作：需要松开再按。自主任务失去运动许可后撤销租约，需要显式重新启动或接管。完整防护发生防撞数据或绕行故障时，还须先停车、释放控制权，再点击“确认故障恢复”。后续的其他停车原因不能清除这个确认要求。

## 正确性与任务隔离

- 独立停车确认改为检查平面速度 `linear_speed_xy` 和角速度，避免横移未停时误报静止。新车端优先使用带原始测量时刻的控制器速度证据，要求测量发生在停车确认之后。
- 搜索门控携带创建时的控制代次和运动租约身份，只能门控对应导航控制者。旧搜索故障、延迟 hold/release、旧导航结果和看门狗不得切换新驾驶者的模式。
- 人工接管仍先请求停止、撤销旧租约并确认静止，再申请新租约。只有控制器停车和实测静止都确认后，旧搜索或助手队列清理失败才能作为告警返回，不能单独阻止安全接管。
- 无效导航速度、转速、速度比例及跟随偏移不会被转换成正常运动；速度比例为 NaN 不再意外变成满速。
- 设置必须在停止模式、底盘确认静止、没有控制者和地图准备占用时修改。请求值和生效值分开显示；拒绝或保存失败保留原配置，并显示拒绝原因。重启仅加载偏好，控制权、按压和任务不恢复。

## 接口与兼容性

沿用 `/api/avoidance`，新增设置字段 `protection_mode: basic | full`，主动绕行仍为 `enabled`，距离仍为 `trigger_distance_m`。没有 `protection_mode` 的旧文件在首次加载时迁移为基础模式、绕行关闭，控制器应用后保存；覆盖前备份为同目录的 `obstacle-avoidance.json.pre-basic`。含新字段的文件保留用户明确保存的选择。

恢复请求为 `{"acknowledge": "当前 motion_epoch"}`，只在完整防护锁停且传感器恢复、车辆静止时生效。设置响应为待确认，收到匹配的控制器回执后才显示生效。

状态新增 `protection_protocol=2`、`motion_epoch`、`command_valid_until`、`recovery_required`、`sensors_ready`、速度证据、设置拒绝原因和最终输出。`available`同时要求传感器就绪且没有待确认的恢复锁；`output.allowed`表示最近控制周期确实放行非零速度。指令接口的 `accepted`只表示接收并转发，`motion_confirmed=false`，实际运动输出以状态为准。

手动指令除驾驶身份和递增 `drive_seq` 外，必须携带：

- `intent_seq`：每次新按压递增，同一次按住的续发保持不变；松手关闭该按压。
- `motion_epoch`：按下时捕获，续发不能随状态刷新而自动换成故障恢复后的代次。
- `command_deadline`：原样复制车端最新 `command_valid_until`，它是车端单调时钟值，不得用浏览器时间自行计算。每条续发可以使用新收到的期限，但已发出的旧包期限不会改变。

HTTP 入口与最终控制器均检查期限，接收时间不延长原期限。即使一次按压的首包延迟、松手消息丢失，过期首包也不能启动。受限短距任务固定使用创建时的运动代次，只有同一控制者、同一代次仍有效时才能刷新期限，遇干预不能自动恢复。

新后端、前端和车端须配套使用。旧客户端缺少新字段会被拒绝运动，独立停止入口保留；旧车端不会被界面标为已经支持基础/完整模式。

## 证据与验证

现有三个受限动作记录均由几何防撞输出零速度。按当前 25×20 cm 车体重新计算，记录的右侧阻挡点均在车体外、距车体不足 5 cm；没有证据支持把它们过滤掉。详细数值在 `output/safety-basic-implementation/evidence-review.json`。来源究竟是真实近障、安装变换还是车体回波，仍需静止现场观察，本次未将它定性为误检。

| 运动学闭环回放 | `kinematic-replay.json`；模拟雷达、受限加减速、近障停车及障碍消失后的旧按压拒绝，不代表 ROS 仿真或实车验收 |

新增覆盖：无位姿手动驾驶、松手后同按压迟到包、迟到首包、原始期限不续命、持续/短暂数据缺失、无效速度、里程计位姿异常、搜索跨控制者隔离、租约过期、急停、前堵后退、横移、角点转动、完整防护显式确认、设置迁移/拒绝/重启偏好。

当前制动模型沿用原有线减速度 0.3 m/s²，并给旋转不确定性使用 0.3 rad/s² 的模型假设；这两者都不能视为真实底盘验收结果。实车部署前仍需测量制动、采样和传输延迟，核对静态安装变换及外部底盘驱动的失联停车能力，并验证控制循环预算。本次没有 Gazebo/Nav2 闭环仿真或实车验收。

下一次只读采集应先在停车状态记录 3～5 分钟：原始雷达与来源类别、雷达安装变换、里程计位姿和独立速度、源时间与接收时间、控制周期、租约和搜索状态、实际配置及最终输出。后续运动验收需单独安排，不复用会主动驾驶的诊断脚本。

## 备份与回退

`output/safety-basic-implementation/baseline/`是本次实施前的文件快照，包含已有未提交修改；`baseline-status.txt`和`pre-existing.patch`记录当时工作区。`changes.patch`及`stages/`仅记录相对于该快照的本次修改，`manifest.json`记录文件哈希。

阶段补丁用于逐项审阅，控制协议与前后端有配套依赖，不能把中间状态当作可部署版本。回退前先停车、撤销控制权并清空运动意图，先用 `git apply --reverse --check output/safety-basic-implementation/changes.patch`核对，再整体反向应用本次补丁；若文件之后又有修改，应人工合并，不能强制覆盖。恢复外部设置时对照 `.pre-basic`备份，保持停车且不恢复旧任务。不要使用整仓 reset 或批量覆盖快照。
