# InsightRover v4 日志与诊断

主机把运行事件写入独立的 `diagnostics.sqlite3`。Jetson 控制器、Web 节点和启动进程将事件放入内存队列，由后台线程写入分段文件。主机只向绑定车辆的机器鉴权接口拉取事件，事件与续传游标在同一次 SQLite 事务提交。操作审计和助手业务状态仍各自保存在业务库。

## 查找意外停车

在「系统 → 日志与诊断 → 故障诊断」选择车辆、时间范围或任务。打开记录后查看原因码、当前模式、最近运动、策略速度、最终速度、限制条件、控制权和关联链路。按下停止、控制器发布零速度、控制器确认停车和里程计确认静止是不同证据。控制器发布零速度但没有停车后的新鲜里程计时，详情会保留未确认状态。若车辆已经失联或诊断健康报告存在缺口，页面中缺失的阶段只能视为未知。

独立停车使用原有控制器回执和停车后里程计。运动期间发生被动阻断时，记录器在零速度发布后观察 0.8 秒。诊断证据不参与控制。外部驱动器和旧 ROS 消息未提供请求身份时，仅保留能实际观测到的本地原因。

## 查询助手执行

在助手历史打开「查看执行诊断」。执行所有者可查看已脱敏的模型调用、工具、草案、确认、状态变化和车端关联记录。可用 Trace ID 在日志中心查同一链路。新草案将 Trace ID 持久化，后台重启后可恢复。升级前的计划与事件可能缺少关联字段。助手输入、模型回复、工具原始参数和提供方密钥均不进入诊断日志。

## 权限与导出

| 权限 | 用途 |
| --- | --- |
| `diagnostics.read` | 操作员和管理员可读运行摘要与停车证据。车辆和任务关联还受原业务权限约束。 |
| `diagnostics.technical` | 默认管理员可查看脱敏栈帧和技术字段。 |
| `diagnostics.export` | 默认管理员可生成 NDJSON 或 ZIP，需要同时具备读取权限。 |
| `assistant.read` | 从历史查看自己的执行摘要。 |
| `audit.read` | 通过原设置入口查询操作审计。 |

导出使用界面所选车辆和时间，最大 24 小时、5,000 条。ZIP 含运行日志、健康状态、关联任务摘要、导出账户自己的助手业务事件和 `manifest.json`。清单说明来源缺失和结果截断。导出动作本身会写入审计。技术异常只保留类型与栈帧的位置，不含异常自由文本和局部变量。

## 配置与保留

| 配置 | 默认值 |
| --- | --- |
| `DIAGNOSTICS_ENABLED` | `1`。主机设为 `0` 停止采集。 |
| `DIAGNOSTICS_VEHICLE_SYNC` | `1`。主机设为 `0` 停止车端拉取。 |
| `DIAGNOSTICS_LEVEL` | `INFO`。错误及关键停车记录绕过普通级别过滤。 |
| `DIAGNOSTICS_DIR` | 主机沿用本地存储目录，桌面使用应用数据目录下的 diagnostics。 |
| `DIAGNOSTICS_MAX_MIB` | SQLite 主文件最多 48 MiB，可设 4–48 MiB。连同回滚日志预留 128 MiB。 |
| `DIAGNOSTICS_NORMAL_DAYS` / `DIAGNOSTICS_CRITICAL_DAYS` | 7 天 / 14 天。 |
| `VEHICLE_DIAGNOSTICS_ENABLED` | `1`。车端设为 `0` 停止采集。 |
| `VEHICLE_DIAGNOSTICS_DIR` | `~/.local/share/insightrover/diagnostics`。由运行车端服务的账号持有。 |
| `VEHICLE_DIAGNOSTICS_HOURS` | 72 小时。每个生产者两条通道、每通道两个 1 MiB 分段，总计最多 12 MiB。 |

位姿调试的独立文件上限仍是两个 5 MiB 文件，Web 节点以后台线程写入。ROS 原生日志、systemd journal、地图、导航运行记录和旧版本遗留日志按部署环境分别管理。Docker 部署时把诊断目录挂载到持久私有目录，检查服务账号有写权限。诊断模块不会读取系统日志、SSH 凭据或任意文件。

## 降级与回滚

内存队列有上限，错误和关键安全事件有独立队列。断网后车辆保留最近分段，恢复时主机续传并按事件 ID 去重。积压超过保留窗口会出现缺口。磁盘写满、只读或数据库损坏时，控制线程不会等待诊断写盘。诊断页报告失败、丢弃及最后同步时间。业务数据库或系统分区耗尽仍可能影响对应业务服务。

同一车端诊断安装标识更换业务机器人 ID 会隔离积压。确认新绑定后可通过使用新的车端诊断目录开启独立保留周期，旧库按权限另行留存。升级回滚时可先关闭采集，保留诊断库及业务库中的可空关联列，使用原版本业务入口。重新启用时从保留的游标恢复。

## HTTP 接口

`/api/v1/diagnostics` 下提供 `GET /events`、`GET /events/{id}`、`GET /traces/{id}`、`GET /executions/{id}`、`GET /stops`、`GET /health`、`POST /exports` 和 `POST /client-events`。历史页使用 `cursor`，增量查询使用 `after`。车端的 `GET /api/diagnostics/events` 仅接受机器鉴权，不经浏览器兼容代理。
