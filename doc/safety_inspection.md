# YOLO11 巡检、报警与循环巡航

本次使用现有 RGB 摄像头与二维雷达。报警后继续巡航；避障、急停、定位故障仍可让车辆停止。文件运输的装件和取件确认流程保持不变。

## 使用入口

电脑网页：`http://127.0.0.1:5173/`。异常中心显示专项模型加载情况、证据同步状态和历史现场图片。在通知中心主动启用声音后，新异常才会播放短提示音；首次登录不会把历史通知全部播放一遍。浏览器休眠或后台节流可能延迟网页提示。

在地图与导航页面添加巡航站点，设置圈数和每站停留时间。只在收到对应 Nav2 目标的成功结果后计入已到达，停留结束后继续下一站。停留时可以暂停、恢复或取消；恢复剩余停留后继续。完成设定站点不等于满足验收指标，记录中的里程与执行时长须分别达到20米、600秒。暂停时间不计入执行时长。里程来自连续有效的 `/odom`，跳变和断流不计入，未做实车计量校验。

配置通道检查时，让小车停止且没有执行任务。在地图上选择通道中央，目标朝向沿通道，填写实际宽度和小车所需净宽，然后保存检查截面。检查截面前后各0.15米，绑定地图版本；换图后不会套用旧区域。雷达点在其采集时间转换到地图坐标，仅使用预设前向视场内的点；在局部0.3米截面中持续占用且估计净宽不足时才产生事件。相机视场默认70度、相对车头偏角0，须通过现场外参和视场核验。事件额外保存雷达点与区域快照；未核验前不把同期照片视为覆盖障碍的证明。二维雷达的扫描平面不能覆盖高处或低矮障碍，也不能判断物品性质。

## 识别与证据链

巡检线程在停止、导航模式下读取现有摄像头服务的最新JPEG，不再次打开USB设备。自动驾驶、颜色跟随和人物跟随仍保留其原有摄像头所有权。识别线程不发布运动命令。

专项权重必须配置为本地文件，并显式声明模型真实标签到 `smoke_fire`、`fallen_person` 的映射。通用COCO模型、交通灯模型和单独的人体框均不能作为三类异常达标依据。权重缺失或标签不一致时，页面显示不可用，不自动下载替代模型。

配置位置为车端 `~/.ros/insightrover/safety-vision.json`。参考 `config/safety-vision.example.json`。烟火专项模型训练后可按下面的结构配置，路径须替换为实际训练产物；此示例不是已部署权重：

```json
{
  "enabled": true,
  "rate_hz": 5,
  "confirm_sec": 2,
  "clear_sec": 10,
  "models": [{
    "path": "/absolute/path/to/trained-yolo11-fire-smoke.pt",
    "class_map": {"smoke": "smoke_fire", "fire": "smoke_fire"},
    "confidence": 0.5,
    "validation": "not_evaluated"
  }],
  "corridors": []
}
```

倒地模型使用独立的训练权重，真实标签须包含倒地类别再配置映射；不使用“人框横放”规则冒充已验证能力。低机位、多人、遮挡、弯腰、蹲下、坐地、正常躺卧与已经倒地的情况，都需要单独检查。

候选默认持续2秒才确认；短暂断帧会打断候选累计。同一持续异常只上报一次，消失10秒后重新出现才形成新一轮。车端SQLite队列同时保存事件和现场JPEG，后台先保存图片、提交异常和通知，再确认车端队列。帧级错误会退避重试，临时落盘失败的事件与图片保留在内存并重试，落盘前不能重配识别；这一内存缓冲在进程退出时不具备持久性。断网、后台重启、确认响应丢失后按固定事件ID补传，已入库事件不重复生成通知。事件只记录发现时的机器人位置，不能当成异常目标的精确坐标；定位缺失时明确注明。

后台每2秒同步车端队列；网页每3秒读取通知。后台确认后清空车端图片，最多保留1000条已确认事件的元数据；SQLite复用空闲页，不主动缩小文件。未确认事件不自动删除，断网积压仍需监测磁盘余量。异常完成处理或忽略时，网页要求填写说明。

新增车端接口为 `/api/safety/status`、`/api/safety/events`、`/api/safety/events/ack` 和 `/api/safety/corridors`；业务端通过现有登录权限访问 `/api/v1/incidents/safety/status`、`/api/v1/incidents/safety/corridors`。巡航执行请求新增 `cycles`（1–100）与 `dwell_sec`（0–600），旧请求默认1圈、不停留。

## 专项训练与验证

烟火数据从D-Fire公开镜像下载，保留固定版本、SHA256和来源说明；镜像许可证描述与原作者不同，以原作者说明及原图权利边界为依据，不据镜像元数据重新分发。标签顺序由原作者 `Fire-Detection/data/dfire.yaml` 核实为0烟、1火。

`scripts/fetch_dfire.py` 下载并校验；`scripts/prepare_dfire.py` 审核标签和图片，将越界框裁到图像范围并记录修正，精确去重并按感知近似分组。AoF视频帧和PublicDataset来源全部留作外部测试，原始测试集不进入训练；剩余WEB训练来源按整组划分训练/验证。WEB缺少原始场景ID，感知近似分组不能证明场景完全独立，公开数据成绩不能替代现场验收。

`scripts/train_safety_yolo11.py` 固定YOLO11、保存训练参数、最佳权重摘要和独立测试指标。训练电脑已检查为RTX4060 Laptop 8GB；车端由用户确认是Orin Nano 8GB，JetPack尚未核验。公开训练不自动部署，FP16需在核验车端软件栈后导出；INT8需另测召回下降。

正式验收需额外统计每类事件召回、每小时误报、从异常可见到报警的延迟，以及推流、导航同时运行时的P50/P95延迟、内存和温度。现场数据按人员、场景、整段录像划分。烟雾、火焰和倒地模拟样例仅代表受测场景。

## 安装与现场检查

`启动系统/上传巡检更新.cmd` 在本机提示SSH密码，将当前代码上传至新的独立目录并检查构建；不切换现有服务、不控制小车。上传成功后先核对真实主板、JetPack、驱动、摄像头、雷达安装方向及配置，再准备静止启动。原程序和地图保留用于回退。

截至本次本地交付，车端SSH尚未认证，8080未监听；未完成上传、车端推理、静止报警或自主巡航实测。距离、时间、成功率和三类异常的实车指标均不能标记通过。

本轮烟火数据审核结果：训练6934张，验证1235张，外部测试13340张；排除18张无效标注图片，裁正379个越界框，全部处理保留审计清单。当前启动的是YOLO11n专项训练，60轮、batch16、workers0，尚无最终测试指标，未部署。倒地专项模型仍未训练或加载，不能宣称三类均已识别。
